## 1. Purpose and Scope

CertGrinder is a gamified certification training simulator built as a companion product to CertDrill. It targets IT professionals preparing for certifications across Enterprise Architecture, Cloud, IT Service Management, and AI/Security domains. The product uses a Reigns-style swipe mechanic where users make binary decisions in organizational crisis scenarios, with outcomes affecting four resource meters. Incorrect balance management ends the game.

**In scope:** Scenario-based gameplay, episode progression, mentor personalities, progress persistence, content generation tooling.  
**Out of scope:** User authentication, social features, payments, mobile native apps, content authoring UI (handled by CLI scripts).

---

## 2. Architecture Principles

| # | Principle | Rationale |
|---|-----------|-----------|
| P1 | Offline-first state | localStorage is the primary state store; DynamoDB is a sync target. API failure must never break gameplay. |
| P2 | Static content pipeline | Scenario and question content is generated once and committed as JS files. No CMS or runtime content fetching. |
| P3 | Infrastructure as code | All AWS resources are defined in CDK. No manual console changes. |
| P4 | Serverless compute | No servers to manage — Lambda + API Gateway covers all backend needs at this scale. |
| P5 | Single branch, direct push | Main branch only. CI/CD triggers on every push. No pull request requirement. |
| P6 | Glassmorphism design system | All UI components derive from a shared `glass` token object. No per-component style overrides. |

## Phase B — Business Architecture

### B1. Business Context

| Item | Value |
|------|-------|
| Product | CertGrinder — gamified certification simulator |
| Sibling product | CertDrill — Q&A drill trainer (`github.com/salppa/certdrill`) |
| Target users | IT professionals studying for certifications (TOGAF, Azure, AWS, GCP, COBIT, ITSM, SABSA, etc.) |
| Business goal | Increase certification pass rates through emotional engagement and decision-based learning |
| Differentiation | Reigns-style swipe mechanic makes studying feel like gameplay, not rote memorisation |
| Content source | Scenarios generated by Claude Opus 4.7 API; questions and overviews sourced from CertDrill |
| Key constraint | Corporate proxy environment — all outbound HTTPS requires SSL verification bypass per tool |

### B2. Business Capabilities

| ID | Capability | Description |
|----|-----------|-------------|
| BC1 | Certification simulation | Present realistic organisational scenarios tied to certification domains |
| BC2 | Consequence learning | Every decision shows a consequence — users learn cause and effect, not just correct answers |
| BC3 | Episode progression | Content unlocks sequentially; earlier episodes must be completed before later ones |
| BC4 | Progress persistence | User progress survives browser refreshes and returns across sessions |
| BC5 | Mentor personality | Each domain has a mentor with four moods that react to user decisions |
| BC6 | Content generation | Administrators can generate new scenarios for any module using the Claude API |
| BC7 | Study materials | Overview HTML pages and question banks are accessible as reference material |

### B3. Business Process Catalog

| ID | Process | Actor | Steps |
|----|---------|-------|-------|
| BP1 | Study session | Learner | Open app → select module → select episode → read monologue → swipe through scenarios → complete or fail episode |
| BP2 | Progress recovery | Learner | Return to app → episode lock state restored from localStorage (DynamoDB sync in background) |
| BP3 | Game over recovery | Learner | Resource meter hits 0 or 100 → GameOver screen → mentor reaction → return to episode select |
| BP4 | Content generation | Content admin | Set `ANTHROPIC_API_KEY` → run `generate_scenarios.py --module <id>` → commit output JS file |
| BP5 | Deployment | Platform owner | Push to `main` → GitHub Actions builds and deploys to S3 + CloudFront automatically |
| BP6 | Infrastructure change | Platform owner | Edit CDK stack → push to `main` → `deploy-infra` job runs `cdk deploy` |

### B4. Organisational Roles

| Role | Responsibilities | System interaction |
|------|-----------------|-------------------|
| Learner | Studies for certifications, plays through episodes | All screens — Dashboard, ModulePicker, EpisodeSelect, ReignsScreen, GameOver, EpisodeComplete |
| Content admin | Generates scenarios, updates question banks | CLI: `generate_scenarios.py`; commits files to repo |
| Platform owner | Manages infrastructure, secrets, deployments | AWS Console, CDK, GitHub Secrets, GitHub Actions |

## Architecture Decisions Log

| ID | Decision | Rationale | Date |
|----|----------|-----------|------|
| AD-01 | localStorage as primary state, DynamoDB as async sync target | API failure must never interrupt gameplay; offline resilience is non-negotiable | 2026-05-26 |
| AD-02 | CloudFront in front of S3 with OAC; S3 public access blocked | HTTPS enforcement, edge caching, no direct S3 URL exposure | 2026-05-27 |
| AD-03 | Scenario content committed as static JS files, not stored in DB | Eliminates runtime content latency; scenarios change infrequently; simpler pipeline | 2026-05-28 |
| AD-04 | `allowOrigins: ['*']` (temporary) | Unblocked development without knowing final CloudFront URL at CDK deploy time | 2026-05-27 |
| AD-05 | Separate GitHub repos for CertDrill and CertGrinder | Different deployment targets, CI/CD pipelines, and technology choices; shared content copied not imported | 2026-05-28 |
| AD-06 | DynamoDB `RETAIN` removal policy + PITR enabled | User progress must not be lost on accidental stack deletion | 2026-05-27 |
| AD-07 | Dynamic `import()` for scenario JS files | Enables per-module code splitting; Vite tree-shakes unused scenarios from initial bundle | 2026-05-26 |
| AD-08 | Sympathy delta = `sign(net resource delta) × 5` | Simple heuristic — net positive decisions increase mentor affinity, net negative decrease it | 2026-05-26 |
