🏗️ Plan & Manage Azure AI Solutions

Azure AI Foundry Architecture

🏢
Hub Shared resource
Top-level governance layer. Holds shared connections to Azure services, managed compute, and security settings. One hub serves multiple teams/use cases.
📁
Project Scoped workspace
Created inside a hub. Inherits hub connections. Where you build flows, deploy models, run evaluations, and develop agents. Scoped to a team or app.
🔗
Connections
Securely stored references (endpoint + credentials or managed identity) to linked services: Azure OpenAI, Azure AI Search, Azure Storage, custom APIs. Referenced by name in flows — no secrets in code.
🚀
Deployments
Named configuration mapping a model version to a capacity tier (Standard / PTU / Serverless). Makes the model callable via REST API.

Exam tip: HTTP 429 errors = quota exhausted. Check Remaining Tokens metric in Azure Monitor. PTUs guarantee throughput and eliminate throttling for production workloads.

Authentication — Managed Identity Pattern

✅ Managed Identity (recommended)
App gets an Entra ID token automatically. Assign Cognitive Services User or Azure AI User RBAC role on the Azure OpenAI resource. No secrets to store or rotate. Use DefaultAzureCredential in SDK.
⚠️ API Key (avoid in production)
Key stored as a secret must be rotated, protected, and never committed to source control. Acceptable only for local development or quick prototypes. Store in Key Vault if used.

Prompting Techniques

Zero-shot
Task description only, no examples. Good for simple, well-understood tasks with capable models.
Few-shot
Include 2–5 worked input→output examples. Best for consistent format, structured extraction, or domain style.
Chain-of-thought
"Think step by step before answering." Dramatically improves multi-step reasoning, maths, logic tasks.
System message
Sets persona, rules, constraints, output format. Applied to every turn. Primary behavioural control mechanism.
Prompt caching
Repeated identical prompt prefixes (e.g. long system message) are cached — reduces latency and cost on subsequent calls.
Function calling
Model returns structured JSON to signal which function to call. App executes; model incorporates result. Enables live data access.

RAG vs Fine-tuning — When to Use Each

📚 RAG (Retrieval-Augmented Generation)
✓Knowledge updates frequently (weekly, daily)
✓Must cite specific source documents
✓Knowledge base too large for context window
✓Need to verify factual accuracy against sources
✗Does not change model weights or style
⚙️ Fine-tuning
✓Consistent output format/schema difficult to prompt-engineer
✓Domain-specific writing style or tone required
✓Reduce token usage on repetitive structured tasks
✗Not for frequently updated factual knowledge
✗Requires labeled training data; expensive to update

RAG Pipeline — Step by Step

1
Chunk
Split docs into focused segments (512–1024 tokens)
2
Embed
Call embedding model → float vector per chunk
3
Index
Store vectors in Azure AI Search vector index
4
Retrieve
Embed user query → top-k cosine similarity search
5
Augment
Inject retrieved chunks into prompt context
6
Generate
Model responds grounded in retrieved facts
Chunking matters: Embedding an entire 50-page document produces one averaged vector — retrieval precision collapses. Focused chunks (one topic per chunk) produce tight vectors that retrieve precisely relevant content. Minimum: 512 tokens. Maximum: embedding model's token limit (e.g. 8,191 for text-embedding-3-large).

Built-in Agent Tools — When to Use Each

💻 Code Interpreter
Sandboxed Python execution. Agent writes + runs code to analyse data, generate charts, do maths, or process files. No external infrastructure needed. Use for: data analysis, CSV processing, calculations, chart generation.
🔍 File Search
Auto-chunks uploaded files, generates embeddings, builds managed vector store. Agent retrieves relevant chunks semantically. Use for: Q&A over large document collections without building a RAG pipeline manually.
🌐 Bing Grounding
Agent queries Bing Search for real-time web content beyond training cutoff. Use for: current news, live stock prices, recent events, public information that changes frequently.
⚡ Function Calling
Agent returns structured JSON to signal which function to call and with what args. App executes the actual API/DB call and returns result. Use for: any internal system — HR APIs, CRM, ERP, databases.

Semantic Kernel (Python / C# / Java) is Microsoft's open-source SDK for agentic apps. Key abstractions: Plugins (callable functions with schemas), Planner (auto-decomposes goals into plugin calls), Memory (vector store connectors), Kernel (DI container wiring everything together).

Prompt Injection & Security

🔴 User Prompt Attack (Jailbreak)
Malicious user message tries to override system instructions: "Ignore all previous instructions and…" Detected by Prompt Shields — User Prompt Attack detection.
🔴 Document Attack (Indirect Injection)
Instructions hidden inside a retrieved document or web page attempt to hijack the agent mid-RAG-pipeline. Detected by Prompt Shields — Document Attack detection. Specific RAG risk.

Image Generation & Multimodal Reasoning

🎨 DALL-E (Azure OpenAI)
Generates photorealistic images from text prompts. Called via images/generations endpoint on an Azure OpenAI DALL-E deployment. Not Azure AI Vision — a separate service entirely.
🧠 GPT-4o with Image Input
Native multimodal — processes text + images in one model. Supports image grounding (returns bounding boxes for referenced objects). Best for open-ended visual reasoning and complex Q&A over images.
GPT-4o vs Azure AI Vision: Use Vision for structured, high-throughput tasks with defined outputs (tags, bounding boxes, OCR). Use GPT-4o for open-ended reasoning — "explain what is unusual in this scene" or "compare these two product photos."

Specialised Vision Services

👤 Azure AI Face API
Detect: bounding box + attributes (age estimate, emotion, glasses). Identify: 1:N search against a PersonGroup — who is this person? Verify: 1:1 — are these two faces the same person? Find Similar: find lookalikes without named identity.
🎬 Azure AI Video Indexer
Extracts comprehensive insights from video: transcript, speaker IDs, face detection, OCR, brand/logo recognition, shot/scene detection, topic segments, sentiment. No single Vision API call covers this breadth.
🎯 Azure AI Custom Vision
Train custom classification or object detection models on your labeled images. Min ~15 images/class. For objects the pre-built Vision model doesn't recognise (e.g. proprietary equipment, specific product SKUs).
🛡️ Content Safety — Images
Classifies uploaded images across Hate / Sexual / Violence / Self-harm with per-category severity scores (0–6). Configurable thresholds for moderation enforcement. Purpose-built for content policy at scale.

Sentiment Analysis — Levels of Granularity

Document level
Overall sentiment of the full text: Positive / Negative / Neutral / Mixed with a confidence score.
Sentence level
Sentiment per sentence, allowing mixed-sentiment documents to be analysed phrase by phrase.
Opinion Mining (aspect)
Identifies specific aspect + opinion pairs: "battery life is great" → aspect: battery life, sentiment: positive. Critical for product feedback analytics.

ModeHow it worksStrengthsWeaknesses
BM25 (keyword)Term frequency × inverse document frequency rankingExact matches, product codes, names; fast; freeMisses synonyms, paraphrasing, semantic meaning

Azure AI Search — Key Components

📐 Skillset
AI enrichment pipeline applied during indexing. Skills: OCR (extracts text from images), NER, key phrases, language detection, entity linking, custom skills (Azure Functions). Enriched fields are indexed alongside raw content.
🗄️ Knowledge Store
Persists AI-enriched content (extracted entities, translations, captions) to Azure Table Storage or Blob Storage as projections. Makes enriched data available to Power BI, ADF, and other tools independently of the search index.
📊 Vector Index
Stores high-dimensional float vectors (embeddings) for each document chunk. Enables cosine similarity search at query time. The foundation of any RAG retrieval pipeline on Azure AI Search.
🏆 Semantic Ranking
Language model re-ranks the top-50 BM25 candidates for deeper semantic relevance. Understands "myocardial infarction" = "heart attack" without synonym maps. Separate billing; add-on to any index.

Hybrid Search — How RRF Works

1
BM25 query
Keyword search → ranked list A
2
Vector query
Embed query → cosine sim → ranked list B
3
RRF merge
Score = Σ 1/(rank+60) across both lists
4
Combined list
Documents in both lists rank highest
5
Optional: Semantic re-rank
LM re-scores top-50 for intent alignment
