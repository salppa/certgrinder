🔄 The ADM Cycle

The Architecture Development Method is the core of TOGAF — an iterative, cyclical process for developing and managing enterprise architectures. Requirements Management sits at the centre and feeds every phase.

TOGAF ADM — Requirements Management feeds and draws from every phase. P (Preliminary) sets the foundation before the cycle begins.

📋 All ADM Phases — Purpose & Key Outputs

DTechnology ArchitectureMap applications and data onto technology infrastructure.Technology Architecture Document, Technology Portfolio Catalogue, Infrastructure Diagrams, Platform Decomposition
EOpportunities & SolutionsIdentify delivery vehicles (projects, programmes), perform gap analysis, create initial roadmap.Initial Architecture Roadmap, Work Package definitions, Gap Analysis results, Architecture Definition Document (draft)

🏗️ The Four Architecture Domains (BDAT)

B — Business Architecture
Business strategy, governance, organisation, and key processes. Answers: what does the business do and how is it structured? Outputs: capability maps, process models, org charts.
D — Data Architecture
Structure of logical and physical data assets and data management resources. Answers: what information exists and how is it managed? Outputs: data entity/component diagrams, data dictionaries.
A — Application Architecture
Blueprint for applications to be deployed, interactions between them, and relationships to business processes. Outputs: application portfolio catalogue, communication diagrams.
T — Technology Architecture
Logical software and hardware capabilities required to support the data and application layers. Outputs: technology portfolio, infrastructure diagrams, technology standards catalogue.
💡 Memory trick — BDAT: Think "Business Drives Applications on Technology" — each layer depends on the one above it. Business requirements drive data needs, which drive application choices, which are hosted on technology.

📦 Artifact Types in the Architecture Repository

Catalogues
Structured lists of elements — Technology Standards Catalogue, Application Portfolio Catalogue, Business Service/Function Catalogue. Document the inventory of building blocks.
Matrices
Show cross-relationships — Actor/Role Matrix, Business Interaction Matrix, Application/Organisation Matrix. Answer "who does what with what".
Diagrams
Visual representations at each level — Business Footprint Diagram, Data Flow Diagram, Application Communication Diagram, Technology Decomposition Diagram.
Architecture Building Blocks (ABBs)
Reusable components defined at the architectural level. Technology-independent. Become Solution Building Blocks (SBBs) when implementation-specific.
Architecture Definition Document
Master document describing the baseline and target architectures. Drafted in Phase E, finalised in Phase F. The primary formal output of an ADM cycle.
Architecture Roadmap
Timeline of work packages moving from baseline to target. First created in Phase E, refined in Phase F. Shows Transition Architectures as intermediate states.

⚠️ Exam Memory Tricks

Phase C = Information Systems — NOT "Computer Systems". C covers Data Architecture AND Application Architecture as two sub-phases. The exam tests this constantly.
Phase E = Opportunities & Solutions — NOT "Execution". This is the first phase where you plan HOW to implement — not the implementation itself.
Phase G = Governance — The architect OVERSEES implementation, not performs it. Phase G produces Architecture Contracts and compliance reviews.
RM is not a phase — Requirements Management is a continuous process, not a sequential phase. It feeds into and draws from every other phase simultaneously.
Statement of Architecture Work vs Architecture Vision — The Statement of Architecture Work is the formal agreement to proceed (like a project charter). The Architecture Vision is the high-level description of what you're building.
