🏛️ What is Enterprise Architecture?

TOGAF defines Enterprise Architecture as "a well-defined practice for conducting enterprise analysis, design, planning, and implementation, using a comprehensive approach at all times, for the successful development and execution of strategy."

EA answers four fundamental questions: What does the organisation do? (Business Architecture) What information does it need? (Data Architecture) What applications support it? (Application Architecture) What technology runs it? (Technology Architecture) — the BDAT model.

🏗️ TOGAF Framework Structure

Architecture Development Method (ADM)
The core iterative process. 10 phases (P, A–H, RM). Provides a tested, repeatable process for developing enterprise architecture. See TOGAF Basics for full ADM detail.
Enterprise Continuum
A classification system for architecture and solution artefacts. Shows the spectrum from generic (Foundation) to organisation-specific. Includes Architecture Continuum and Solutions Continuum.
Architecture Repository
Structured storage for all architecture work products. 6 classes of content. The "single source of truth" for the architecture practice.
Reference Models
TRM (Technical Reference Model) and III-RM (Integrated Information Infrastructure RM). Ready-made reference architectures for common needs.
Architecture Capability Framework
How to establish and operate the architecture practice itself — roles, skills, governance structures, Architecture Boards, processes.

🗄️ Architecture Repository — 6 Classes

ClassContents
Architecture MetamodelThe rules and definitions for the architecture practice — what types of artefacts exist, how they relate.
Architecture CapabilityParameters, processes, roles, and responsibilities that define the architecture practice in this organisation.
Architecture Landscape3 levels: Strategic (long-term, high-level), Segment (area/division), Capability (detailed, specific). All architectures live here.

👥 Stakeholder Management

TOGAF uses a structured approach: Stakeholders have Concerns. Viewpoints define how concerns are addressed. Views are the actual representations created from those viewpoints.

🏛️ Architecture Governance

Architecture Board
Cross-organisational body that oversees architecture implementation. Reviews compliance, grants dispensations, resolves disputes. Chair is typically the Chief Architect or CIO.
Architecture Contract
Joint agreement between the development team and architecture sponsors on the deliverables, quality, and fitness-for-purpose of the architecture. Signed in Phase G.
Compliance Reviews
Formal assessments to ensure projects conform to the approved architecture. Carried out in Phase G (Implementation Governance). Can result in Dispensations (approved deviations).
Architecture Principles
Stable, general rules that govern architecture decisions. Set in Phase P (Preliminary). Example: "Data is an asset", "Technology independence", "Reuse before buy before build".

🔗 TOGAF Relationships to Other Frameworks

FrameworkRelationship to TOGAF
ITIL 4ITIL governs IT service management (running services). TOGAF governs how IT services are designed and structured. TOGAF produces the architecture; ITIL operates against it.
COBIT 2019COBIT provides governance and management objectives. APO03 (Managed Enterprise Architecture) is the COBIT objective directly supported by TOGAF.
Zachman FrameworkZachman is a 2D classification system (6 perspectives × 6 aspects). TOGAF is a process framework. They complement: Zachman classifies artefacts; TOGAF tells you how to create them.
SAFe (Scaled Agile)TOGAF 10 introduced guidance on using ADM in agile contexts. Architecture runway concept in SAFe aligns with TOGAF's Segment and Capability architectures.
