🌍 Global Infrastructure

GCP is organised into a three-tier hierarchy: Multi-regions → Regions → Zones. Most resources are deployed into a region or zone. Choosing the right location affects latency, compliance, and availability.

🌏
Multi-Region
e.g. "EU" — geographic grouping for highest redundancy. Used for Cloud Storage multi-regional buckets.
↓
🗺️
Region
e.g. "europe-west1" — collection of 3+ zones. Independent power, cooling, networking. Deploy here for HA.
↓
🏢
Zone
e.g. "europe-west1-b" — a single data center. Deploy across zones for fault tolerance.
Exam tip: Regions = multiple zones. Zones = isolated within a region. Multi-region = spans multiple regions. Google's network interconnects all of them with premium low-latency fibre.

🏗️ Resource Hierarchy & Projects

Every GCP resource must belong to a Project. Projects are grouped into Folders which sit under an Organisation node. IAM policies and billing flow down this hierarchy.

🏛️
Organization
Root node. Maps to a Google Workspace or Cloud Identity domain. Policies here apply to everything below.
↓
📁
Folder
Optional grouping (e.g. by department or environment). Inherits org policies and can add its own.
↓
📦
Project
The unit of billing, API enablement, and access control. Every resource lives inside exactly one project.
↓
⚙️
Resources
VMs, buckets, databases, functions, etc. Inherit IAM from project/folder/org.

💻 Compute Services

🖥️ Compute Engine (IaaS)
Virtual Machines you fully control. Choose CPU, RAM, GPU, OS. Includes Preemptible/Spot VMs (up to 91% cheaper, can be terminated by Google). Supports Live Migration — VMs move across hosts during maintenance with no downtime.
☸️ GKE — Google Kubernetes Engine (CaaS)
Fully managed Kubernetes clusters. Google handles control plane upgrades, scaling, and security patches. Autopilot mode manages node infrastructure too.
🚀 Cloud Run (Serverless Containers)
Run containers without managing servers. Scales to zero when idle. Pay per request. Ideal for stateless HTTP services and microservices.
⚡ Cloud Functions (FaaS)
Event-driven serverless code snippets. Triggered by HTTP, Pub/Sub, Cloud Storage events, etc. No infrastructure to manage.
🌐 App Engine (PaaS)
Platform for web applications. Standard (sandboxed, fastest autoscale) and Flexible (custom runtimes, Docker). Google manages servers, OS, and runtime patches.

🗄️ Storage Services

Cloud Storage (Object Storage)

Globally available, highly durable object storage. Organised into Buckets. Four storage classes based on access frequency:

ClassMin DurationAccess FrequencyUse Case
StandardNoneFrequentHot data, web assets, analytics input
Nearline30 days~MonthlyBackups accessed monthly
Coldline90 days~QuarterlyDisaster recovery archives
Archive365 days~YearlyLong-term regulatory archives
💾 Persistent Disk
Durable block storage attached to Compute Engine VMs. Standard (HDD) or SSD options. Survives VM deletion.
⚡ Local SSD
Physically attached to the host server. Extremely fast but ephemeral — data lost if VM stops.
📂 Cloud Filestore
Managed NAS (Network Attached Storage). NFS-compatible shared file system for VMs and GKE.

📊 Data & AI Services

📈 BigQuery
Serverless, petabyte-scale data warehouse. Pay per query. Separates compute from storage. Supports SQL, ML (BigQuery ML), and BI Engine for fast dashboards.
📨 Pub/Sub
Global asynchronous messaging. Decouples publishers from subscribers. Foundation for event-driven architectures and streaming pipelines.
🔄 Dataflow
Managed Apache Beam service for batch and stream data processing. Used for ETL, real-time analytics pipelines.
🐘 Dataproc
Managed Spark and Hadoop clusters. Spins up in 90 seconds. Migrate on-premises big data workloads with minimal change.
🤖 Vertex AI
Unified ML platform. Train, deploy, and manage models. Includes AutoML (no code needed), pre-built APIs (Vision, Speech, Translation, NLP), and Vertex AI Pipelines for MLOps.
📊 Looker
Business intelligence and data visualization. Embedded analytics. Connects to BigQuery and other sources. Google's BI product after 2019 acquisition.

🔒 IAM & Security

Identity and Access Management (IAM)

IAM answers: "Who can do what on which resource?" It works by binding a Principal to a Role on a Resource.

👤 Principals (Who)
Google Account (person), Service Account (app/VM), Google Group, Google Workspace domain, Cloud Identity domain, allUsers / allAuthenticatedUsers.
🎭 Roles (What)
Basic: Owner / Editor / Viewer (avoid for prod). Predefined: Fine-grained per service (e.g. roles/storage.objectViewer). Custom: Build your own from individual permissions.
🔑 Service Accounts
Identity for non-human users (VMs, apps, pipelines). Has its own email address. Authenticate with keys or Workload Identity Federation (recommended).
Least Privilege: Always grant the minimum permissions needed. Use predefined roles over basic roles. Avoid owner role on production projects.

🌐 Networking

🔵 VPC (Virtual Private Cloud)
Global private network for GCP resources. Unlike other clouds, GCP VPCs are global — one VPC spans all regions. Subnets are regional. VPC peering and Shared VPC for cross-project connectivity.
⚖️ Cloud Load Balancing
Global (HTTP/S, SSL, TCP) or regional load balancers. Software-defined, no warm-up needed. Distributes traffic across instances, regions, or backends.
🌍 Cloud CDN
Content Delivery Network built on Google's global edge network. Caches content close to users for lower latency.
🔗 Cloud Interconnect
Dedicated (physical) or Partner (via ISP) private connection from on-premises to GCP. Lower latency and cost than using public internet for high-volume traffic.
📡 Cloud DNS
Managed authoritative DNS with 100% uptime SLA. Supports public and private DNS zones.
Network Service Tiers: Premium = traffic stays on Google's private fibre as long as possible (lowest latency, highest reliability). Standard = traffic uses public internet (lower cost). Premium is the default.

☁️ Cloud Concepts

📦 Service Models
IaaS — you manage OS upward (Compute Engine). PaaS — you manage app code (App Engine). SaaS — you use the software (Gmail, Workspace). FaaS/Serverless — you manage just the function (Cloud Functions, Cloud Run).
💰 CapEx vs OpEx
CapEx (Capital Expenditure) = upfront hardware purchase (on-premises). OpEx (Operating Expenditure) = pay-as-you-go consumption. Cloud converts CapEx to OpEx.
🌱 Sustainability
Google has been carbon-neutral since 2007 and aims for 24/7 carbon-free energy by 2030. GCP data centres are among the most energy-efficient globally (PUE ~1.1).
🔄 Shared Responsibility
Google secures the infrastructure (hardware, facilities, network). You secure your data, access controls, and what you build on top. More responsibility shifts to Google as you move from IaaS → PaaS → SaaS.
